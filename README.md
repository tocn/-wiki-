# 原神 Wiki 文本镜像

BWIKI 原神站(<https://wiki.biligame.com/ys>)的**纯文本镜像**。
只收录 wiki 正文,不纳管任何图片/音视频等媒体资源。

## 数据来源与合规

- 源站:wiki.biligame.com/ys(MediaWiki 1.37.0)
- 已核对 `robots.txt`:允许抓取 `/ys/` 下的条目页;仅取**主命名空间(ns=0)**,
  避开被声明禁止的 `模板:` / `文件:` / `特殊:` / `User:` / `MediaWiki:` 等命名空间。
- 请求间隔 0.8 秒,以 `stealthy_headers` 正常浏览器身份访问,不使用任何绕过手段。
- 站点由腾讯云 EdgeOne 防护,普通裸请求会返回 HTTP 567 拦截页;
  使用 scrapling 的 `Fetcher.get(..., stealthy_headers=True)` 可正常获取。

## 目录结构

```
data/
  pages.jsonl       # 阶段一:ns=0 全量清单(52,021 条,含地图点位)
  targets.jsonl     # 阶段二:过滤后的抓取目标(19,641 条)
  fetch_log.jsonl   # 阶段二:逐页抓取记录(pageid/状态/字节数/时间)
  categories.jsonl  # 阶段四:每条的源站分类
  md/               # ★ 最终交付物:按分类归档的 Markdown
    <大类>/<标题>.md
  index.jsonl       # pageid <-> 标题 <-> 文件 <-> 分类 映射
cache/
  raw/              # 原始渲染 HTML(体积大,不入库,可随时重跑生成)
  orphan/           # 落单产物(未删除,留待人工核对)
scripts/
  01_list_pages.py          # 枚举 ns=0 全部条目
  02_fetch_content.py       # 批量抓取渲染 HTML(限速 + 断点续跑)
  03_html_to_md.py          # 清洗转换,并直接写入分类目录(并行)
  04_fetch_categories.py    # 获取源站分类(50 标题/请求)
  05_report_categories.py   # 分类诊断(只读)
  clean.py                  # 清洗模块(HTML -> Markdown)
  taxonomy.py               # 分类法:源站分类 -> 归档大类 的映射表
```

## 管线用法

```bash
PY="C:/Users/admin/.workbuddy/binaries/python/envs/scrapling/Scripts/python.exe"

$PY scripts/01_list_pages.py            # 1. 枚举条目
$PY scripts/02_fetch_content.py         # 2. 抓取(可重复执行以续跑;--limit N 试点)
$PY scripts/04_fetch_categories.py      # 3. 获取源站分类(可先于转换)
$PY scripts/03_html_to_md.py            # 4. 清洗转换 -> data/md/<大类>/ (并行)
$PY scripts/05_report_categories.py     # 5. 分类诊断:覆盖率、判定来源、一致性校验
```

各阶段均可重复执行:阶段二依据 `fetch_log.jsonl` 续跑;阶段四依据 `categories.jsonl` 续跑;
阶段三整体重算(并行,数千篇约数分钟)。

**阶段三直接写入分类目录**,不产出「扁平中间态」。早期版本先写扁平、再由另一阶段移动,
结果同一篇文章可能同时存在于旧分类目录与扁平位置,移动时顾此失彼、遗留重复副本。
一个文件只应有一个家。非文本页与落单文件均不会被删除,后者移入 `cache/orphan/` 待核对。

## 分类体系

归档**以源站的 MediaWiki 分类为依据**,而非本项目自行划分 —— 分类是站点编者定义的归属。
`taxonomy.py` 中的映射表把源站分类收敛成 12 个可浏览大类,避免目录名冗余与目录数膨胀。

### 判定顺序(逐级降级,来源可查)

1. **`wiki`** —— 依据源站分类。权威,占 95.6%。
2. **`parent`** —— 依据父页面。子页面自身无分类时:
   - 先查「索引页映射」(`PARENT_HINTS`,如 `NPC图鉴/…` → NPC、`幻想真境剧诗/…` → 活动);
   - 再继承父页面自身的分类。
3. **`title`** —— 标题关键词兜底(仅高精度词,如 攻略/心得/指南/教程/圣遗物/武器/怪物)。
4. **`none`** —— 仍无法判定,归入「未分类」。

`index.jsonl` 的 `category_source` 字段记录每篇的实际来源,可用 `05_report_categories.py` 审计。

### 关于「未分类」的残留

`未分类` 约 489 篇(2.5%),主体是**语义长尾**,而非规则疏漏:地名(蒙德/璃月/至冬)、
神系与神话人物(天理/四影/神之心/赤王)、种族与势力(兰那罗/美露莘/愚人众)、
系统机制(元素/属性/聚变/炼金)、节庆(海灯节/羽球节)。这些在源站既无分类,
标题也不含可判定的关键词。**继续用关键词强判会制造错误目录**,故到此为止 ——
要再提升覆盖,只能逐页语义判读,或引入基于页面模板/正文特征的分类器。

**两条设计约定:**

1. **维护性分类不参与归档**(`正在计时的页面`、`待审核`、`含有受损文件链接的页面`、
   `含有嵌入地图的页面` 等)。它们是站点质检标记,不代表内容归属。
2. **判定来源可审计**。`index.jsonl` 的 `category_source` 字段记录每篇的判定依据:
   `wiki` = 依据源站分类(权威);`title` = 源站分类缺位时按标题关键词兜底;
   `none` = 仍无法判定,归入「未分类」。用 `--report` 可查看覆盖率与未映射分类。

## 清洗规则

剔除以下几类**读者不可见或非正文**的内容:

| 类别 | 选择器 / 判据 | 说明 |
|---|---|---|
| 编辑栏与面包屑 | `#bread-edit` + 含「首页」的首层 div | 「阅/编/刷/历」 |
| 站务提示 | `.bg-snm` | 「如果是第一次来…」 |
| 顶部导航 | `.map-dh` | 「角色导航」 |
| 目录 | `.toc` | |
| 站尾导航 | `.navigation-not-searchable` | |
| 内联样式 | `style` / `script` | 否则 CSS 会混入正文 |
| 折叠按钮 | `.ys-collapse-explain` | 「展开/折叠」UI 标签 |
| 隐藏容器 | `.hide` / `.shade` / 内联 `display:none` | 源站存数据用,典型如 `#categoryData`(内嵌地图标记 JSON) |
| 交互地图应用 | `#map-div` | Vue 组件模板(`{{item.markTypeName}}`),无法在 Markdown 中还愿 |
| 整页数据页 | 正文以 `{"` 开头 | 如 `Map4`,通篇地图 JSON,无容器可定位 |

## 已知问题与边界

- **地图内容不收录**:源站的任务/点位页内嵌交互地图,其标记数据(坐标、图标 URL、
  `markType` 等)与组件模板均被剔除。因此 `## 任务接取位置` 一类小节可能是空的——
  这是忠实反映源站该处以地图而非文字呈现,未做任何补写。
- **计时器模板残留**:少量页面含 `52020/11/11 6:00:0…` 一类字符串,属源站模板渲染产物。
- **极短页面**:内容不足 30 字的页面(如仅含版权声明)会被阶段三跳过。
- 阶段三会清理与 `index.jsonl` 不一致的陈旧产物,避免规则收紧后残留过期文件。

## 运维注意

- **不要用 `os.replace` 覆盖已有文件**。本环境的沙箱会把「覆盖已有文件」类操作
  接管到系统回收站(SAFE_DELETE),`os.replace` 必定抛 `WinError 5` 且重试无效。
  写入改用直接截断写(见 `03_html_to_md.py` 的 `write_jsonl`)。
- 仓库体积较大(数万个 Markdown 文件)时,沙箱的写前备份可能超时,
  表现为**已有文件短暂拒写**。稍候重试即可恢复,不是文件损坏。
- 抓取失败多为站点侧 5xx,续跑机制只认 `status==200`,重跑 `02` 即自动补齐。
- **`status==200 但内容为空`不等于失败**:源站存在少量空页面
  (`Test`、`File:*.png`、非条目命名空间等),阶段三会正常跳过。
