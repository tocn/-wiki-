# 多语言文本源调研（世界观名词词典用）

> 调研日期：2026-10-05（**已按 7.1 版本核实时效**）｜ 目的：为「世界观名词词典」寻找**中文语料之外**的对照源，
> 以弥补中文单语语料的结构性盲区（如「三宝磨」的英文名 SAMPO 无法在中文正文中获得）。

## 一、要解决什么问题

现有 `data/md/` 为**纯中文 wiki 文本**，两类信息天然缺失：

1. **外文原名 / 拉丁字母缩写**（如 亚原子质能衍构核心 = Subatomic Assembling Mass-energy Patterning Orb = SAMPO）；
2. **不同语言版本的措辞差异**（可用于交叉验证译名、发现命名梗）。

→ 需要一个能给中文文本配到**同一内容的其它语言版本**的对照源。

## 三、关键区分：TextMap ≠ 结构化数据库

- **TextMap**（Dimbreath 等）：游戏内**全部文本**的 `hash → 本地化字符串` 映射，**涵盖任务对话、游戏内书籍、道具描述、NPC 台词**——**这才是能覆盖「坎瑞亚」「魔神战争」这类世界观名词的**。同一 hash 在不同语言文件里就是**同一句文本的不同语言版本**，可做**精确对齐**。
- **结构化数据库**（genshin-db / Project Amber / dvaJi）：按 角色 / 武器 / 圣遗物 / 材料 组织，属性为主；世界观名词多不在其中。

→ 结论：**要补世界观名词的多语言对照，应主攻 TextMap。**

## 四、推荐用法（hash 对齐）

1. 取 `TextMapCHS.json` 与 `TextMapEN.json`（按需再加 JP/KR/…；俄/泰为分片文件 `*_0/_1`，需拼接）；
2. 建反向索引：`中文文本 → hash → 其它语言文本`；
3. 词典中每个名词：先在中文字料定位其出现句 → 匹配 hash → 取出英文等版本；
4. 例：`亚原子质能衍构核心` → hash → `Subatomic Assembling Mass-energy Patterning Orb` → 缩写 **SAMPO** → 反查北欧神磨 Sampo。

## 五、时效性核查（本次踩过的坑，务必保留）

- **教训一：评估数据源必须核对「当前时间 vs 源最后更新时间」。**
  本次首轮调研曾把 **UIGF-org/GenshinData** 当作首选（当时只看到"6.1 / 2025-10"，未意识到**当前已是 2026-10**）。复核发现其**最后提交停在 6.1、整整停更一年**，与当前 7.1 差了一整年 → 已剔除。
- **教训二：看仓库状态须看 main / HEAD，勿被历史 commit 快照 URL 误导。**
  首轮曾据一个**固定历史提交的 URL**（`tree/<sha>`）把 **DimbreathBot/AnimeGameData 误判为 5.5、数据滞后**；复核 main 分支实为 **7.1（2026-10-01）**，是当前最活跃、最全的源。
- → **结论**：数据源清单必须**带"最后更新时间"字段并定期复核**；跨一年以上未更新的源默认不可用。

## 六、合规提示（重要）

- 上述 TextMap 类数据均为**社区对游戏客户端的逆向解包**，**版权属米哈游**，长期处于灰色地带（Dimbreath 系仓库历史上多次被 DMCA / 迁移）。
- 本项目现状是**合规抓取 wiki 公开页面**。引入客户端 dump 会**改变项目的合规性质**。
- 建议的隔离原则：
  - 客户端数据**仅作本地比对用途**，**不纳入仓库、不作为交付物分发**；
  - 交付物中**只保留对照结论**（如英文名），并标注其**来源层级为 E（外部设定）**；
  - 优先考虑**更合规的替代**：抓取**多语言官方 wiki**（如英文 Fandom）——公开、可抓，与现有定位一致，但覆盖依赖编辑者、不如 TextMap 全。

## 七、两条路线对比

| 路线 | 覆盖 | 合规 | 成本 |
|---|---|---|---|
| **A. 多语言 Wiki 抓取**（如 Fandom 英文站） | 中（依赖编辑者，但含 lore 页） | ✅ 与现项目一致 | 中 |
| **B. 客户端 TextMap**（Dimbreath，7.1） | **全**（15 语，逐句可对齐） | ⚠️ 灰区，须隔离 | 低（下载 + 建索引） |

→ 倾向：**B 用于本地校验、A 用于可公开交付**；交付物只承载结论。
